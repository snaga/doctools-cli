# 0007. MuPDF (go-fitz) による高精度 PDF テキスト抽出の採用

- ステータス: 承認済み (Accepted)
- 日付: 2026-11-22

## コンテキスト (Context)
これまで PDF のテキスト抽出には純 Go 製の `pdfcpu` を使用していた。
しかし、日本のビジネス文書やスライド PDF において、以下の問題が頻発していた：
1. **未解決 CID / 文字化け**: フォントの ToUnicode CMap が正しく解決されず、日本語テキストが記号や文字化けとして抽出される。
2. **描画オペレータの混入**: PDF の内部描画コマンド（生 PostScript 類似オペレータ）がテキスト内に紛れ込み、全文検索（FTS）のインデックス品質を著しく低下させる。
3. **ディスク I/O オーバーヘッド**: `pdfcpu` の一時ファイル出力経由によるディスク I/O 負荷。

## 決定 (Decision)
PDF ページからのテキスト抽出（`pkg/pdf`）および全文検索インデックス構築（`pkg/fts`）のテキスト抽出エンジンとして、**MuPDF CGO バインディング (`gen2brain/go-fitz`)** を全面採用する。

## 結果 (Consequences)
### ポジティブ
- PyMuPDF と同等の強力な ToUnicode CMap 解決能力により、日本語テキストの文字化け・描画オペレータ混入がゼロになり、純粋な UTF-8 テキストが得られる。
- 高速なインメモリ走査により、PDF 39ページを約300msでテキスト化・インデックス化可能。
- `bleve` による日本語 N-gram 全文検索の適合率・再現率が劇的に向上。

### ネガティブ / トレードオフ
- ビルド時に `CGO_ENABLED=1` および MuPDF 静的ライブラリ (`.a`) のリンクが必要となる（ただし完全静的リンクにより、外部 DLL 不要の単一バイナリ配布を維持）。

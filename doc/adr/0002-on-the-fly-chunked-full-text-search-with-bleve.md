# 0002. Bleve による On-the-fly チャンク化全文検索と AI ナビゲーション

* Status: Accepted
* Date: 2026-08-11

## Context (背景)

数千ページ規模のドキュメント群（Office, PDF, Markdown, CSV 等）から AI エージェントが的確に必要な情報を引き出すにあたり、従来の「ファイル単位の粗いインデックス」では以下の問題があった：

1. 検索ヒット時にファイル全体が返却され、AI のプロンプトコンテキストを圧迫する。
2. どの章、どのスライド、どのシートに目的の記述があるのかを AI が特定しづらい。
3. 日本語の分かち書きや複合条件（特定シートや特定拡張子での絞り込み）の柔軟性が不足していた。

## Decision (決定事項)

Go 製全文検索ライブラリ `blevesearch/bleve` を採用し、ファイル読み込み時に動的に構造化チャンクを生成する **「On-the-fly チャンク化全文検索」** 機構を導入した。

1. **On-the-fly 階層チャンク化**:
   - Excel: シート単位＋セルブロック単位
   - PowerPoint: スライド単位＋シェイプ単位
   - PDF: ページ単位
   - Markdown / Text / CSV: 見出し・行ブロック単位
2. **階層型ロケータ (`locator`) & ナビゲーションメタデータ**:
   - 各検索ヒット結果に `file_path`, `unit_name`, `locator` (例: `slide=3`, `sheet=Sheet1!A10:D25`) を付与。
3. **高速な差分更新 (Incremental Update)**:
   - `mtime` およびファイルサイズをトラッキングし、更新・追加されたファイルのみを最小限のオーバーヘッドで再インデックス。
4. **柔軟なクエリ構文 (Bleve QueryString)**:
   - 日本語 N-gram 検索に加え、フィールド指定（`file_type:.pdf AND content:設計`）などの高度検索に対応。

## Consequences (影響と結果)

### メリット
- AI エージェントが検索結果を受け取った際、該当するピンポイントのページやスライド番号を直感的に把握できる。
- 外部の検索サーバープロセス（Elasticsearch や Java 等）を必要とせず、完全ローカル＆高速に動作する。

### デメリット / 制約
- 大規模なドキュメント群を初回ビルドする際は、一定の CPU/ディスク I/O リソースを消費する（タイムアウトおよび拡張子フィルタで制御可能）。

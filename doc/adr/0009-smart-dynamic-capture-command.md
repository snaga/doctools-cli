# 0009. Smart Dynamic Capture コマンドとマルチモーダル VLM 連携

## ステータス (Status)
Accepted (承認済み) - 2026-11-23

## コンテキスト (Context)
近年、Claude 3.5 Sonnet, GPT-4o, Gemini 1.5 Pro など、高度な視覚理解能力（Vision）を備えたマルチモーダル LLM (VLM) が一般化し、ドキュメントのテキストだけでなく「複雑な図表、プレゼンテーションスライド、帳票レイアウト」を画像として直接読み取らせるユースケースが急増している。

しかし、AI エージェントに対するドキュメント画像化機能の提供には以下のトレードオフが存在する：
1. **コンテキストウィンドウ爆発 (Flooding)**:
   画像を MCP の ImageContent（Base64 形式）として無警戒に返却すると、1 ページあたり約 1,000〜1,500 トークン（生テキストとして解釈された場合は十数万トークン）を消費するため、複数ページを一括返却すると会話履歴が急速に圧迫され推論精度が急落する。
2. **Handle-based の認知的摩擦**:
   一方でローカル画像ファイルパス（ハンドル）のみを返却した場合、エージェントは画像を閲覧するために追加のツール呼び出しを強いられ、1 ターンで即座に回答できない。
3. **複数ドキュメント形式のレンダリング差異**:
   PDF は MuPDF (go-fitz) によりゼロ依存・高速に画像化できるが、PowerPoint (.pptx) や Excel (.xlsx) は Office のネイティブ描画エンジン（Windows COM）を要する。

## 決定事項 (Decision)

### 1. 統合ディスパッチャへの `command: "capture"` の追加
`doctools_run` の Enum コマンドに `read`, `search` に続く第 3 のコアアクションとして `capture` を追加する。
対象フォーマットは以下の 3 つに絞り込む：
- **PDF (`.pdf`)**: `go-fitz` (MuPDF) によるゼロ依存・高速ラスタライズ。
- **PowerPoint (`.pptx`)**: Windows COM (`slide.Export`) によるネイティブスライド画像化。
- **Excel (`.xlsx`, `.xlsm`)**: Windows COM (Fit-to-Page PDF エクスポート) ➔ MuPDF ラスタライズによる 1シート=1画像描画。
※テキスト, CSV, HTML などの非対象形式は明確なエラーメッセージを返却する。Office 未導入時は利用不可の旨を親切にエラー案内する。

### 2. Smart Dynamic Capture（動的画像レスポンス制御）
抽出対象のページ数に応じて、レスポンス形式を動的・自動的に切り替える：

| 抽出ページ数 | 挙動 | トークン消費 | エージェント体験 |
| :--- | :--- | :---: | :--- |
| **単一ページ (1枚)**<br>（例: `pages: "3"`） | **MCP ImageContent (Base64) ＋ ファイル保存**<br>・`.tmp/{base}_page_{num}.png` に保存。<br>・同時に MCP `ImageContent` として LLM の視覚にダイレクト注入。 | 約 1,000〜1,500 トークン (安全圏) | **追加ツール呼び出しゼロ！**<br>その場で LLM が図表を視覚認識して即座に回答。 |
| **複数ページ (2枚以上)**<br>（例: `pages: "1-3,5"`） | **ファイルハンドル一覧（テキスト）のみ返却**<br>・全ページを `.tmp/` に画像保存。<br>・各画像のファイルパス、解像度、ファイルサイズのリストのみ返却。 | 約 30 トークン (ほぼゼロ) | **コンテキスト爆発を 100% 防止！**<br>「直接見たいページは単一ページで再指定」するよう誘導。 |

※単一ページ抽出時でも、`options.inline: false` を指定することで Base64 注入を抑制し、ファイルパスのみを取得するオプトアウトを可能とする。

### 3. プリンタ風ページ選択記法 (Printer Page Selection Syntax)
`options.pages` において、`"1"`, `"2-4"`, `"2,5,8"`, `"1-3,5,8-10"` のようなカンマ・ハイフン複合指定をサポートする。
指定ページに存在しない番号が含まれる場合でも、存在するページのみをキャプチャし、不在ページはスキップ警告としてメッセージに添える「寛容モード」を採用する。

## 影響と結果 (Consequences)

### メリット
- **マルチモーダルエージェントの体験最大化**: 見たい 1 ページを即座に「見て」回答できる圧倒的な即応性を実現。
- **決定論的なコンテキスト保護**: 複数ページ指定時はファイルハンドルのみを返すため、エージェントが誤って長大ドキュメントをキャプチャしても安全。
- **シンプルなインターフェース**: `doctools_run` の統一ゲートウェイ思想を崩さず、直感的な `command: "capture"` で全操作を完結。

### デメリット・注意点
- PowerPoint / Excel のキャプチャには Windows + Microsoft Office 環境が必要（非 Windows や Office 未導入時は PDF のみ利用可能）。
